# 轻量经验检查

用于用户明确要求“轻量经验检查”或“只提炼这次返工教训”。普通“开始复盘”仍走完整双阶段协议。检查进行中事件时先标注任务未完成，不替代必需交付。

## 只读流程

1. 读取指定事件的请求、改动、失败、修复和验证证据，限制在已明确项目范围。
2. 只找：修完又返工、错误放行、验证不足，以及有证据的正确实践。没有问题就报告没有可支持的新教训。
3. 对每项区分观察、推断和未知，先核对已有规则是否覆盖；重复失败查明未读取、表述、冲突或检查缺口。
4. 输出至多三个有价值条目，按 [经验记录](lesson-record.md) 给出适用条件、证据、最小改进与观察方法。
5. 列出未验证项并停止。不会自动进入复盘二，不初始化手册、不生成完整反事实/提示词模板、不修改规则、不派生 Agent、不清理资源。

默认只在答复中给出结果。用户明确要求保存时，复用所属项目既有经验或任务记录，遵循该项目写集与 `dev` Git 交付；保存不是实施许可。用户明确要求实施选定改进时，按声明写集交接到 `asm` / `dev` 或领域技能；已有完整复盘的人工阅读停点仍须遵守，不能用轻量模式绕过。

例：用户“只提炼这次返工教训” → 给出一条带证据的教训与未验证项，保持只读。用户“保存这条教训” → 写项目记录并交付；不会顺带修改技能。用户“按这条修复指定技能” → 进入已授权技能维护路线。
