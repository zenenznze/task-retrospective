# 历史案例证据：双阶段复盘的真实来源

本文件是历史设计依据的脱敏摘要，不是运行时的固定任务清单。公开版使用案例编号，省略原始会话 ID、机器路径和私人项目标识；原始记录不随技能发布，读者无法据此独立核验原始会话。未来运行以当前会话和当前项目证据为准。

## 覆盖范围

- 设计时审计了本机会话记录；该审计只覆盖当时可访问的记录，不代表覆盖其他设备或未提供的归档。
- 精确匹配两类用户消息后，确认以下 6 个会话实际出现独立的阶段一和阶段二消息：

| 案例 | 项目类别 | 任务类型 | 复盘二目标参数 |
|---|---|---|---|
| 案例 A | 文档目录清理 | 存储清理与归因 | 非空本地手册路径 |
| 案例 B | 文档发布工作流 | 发布阻塞与流程修复 | 非空本地手册路径 |
| 案例 C | Agent/规则项目 | 规则引用与链接修复 | 空值，后续由用户补路径 |
| 案例 D | 封面技能开发项目 | 技能与凭据流程修复 | 非空本地手册路径 |
| 案例 E | 新闻视频项目 | 视频制作与框架修复 | 空值，后续由用户补路径 |
| 案例 F | 封面技能恢复项目 | 会话检索与恢复修复 | 空值，后续由用户补路径 |

另有案例在阶段一之后直接给出“可以执行双向升级”的自然语言授权，说明继续信号可能不是固定词，但必须表达明确执行意图。

仅检索或引用本机制的对话，不作为完整执行案例计数。

## 共同观察

1. 阶段一都要求停止继续实现、重建全过程、审计规则/项目规则/Skills/工具/模型、人机协作、反事实方案、经验沉淀层级和可验证改进。
2. 阶段一答复后，人类通常会认真阅读，随后用“可以”“继续”“我授权”或补充目标路径进入阶段二；技能不能把第一份答复和第二份执行合并。
3. 阶段二都分成 Agent 运行侧与 Human–Agent 手册侧，要求把建议落到真实文件、测试和主会话统一验收。
4. 复盘二的 `HUMAN_AGENT_PLAYBOOK_TARGET` 出现过非空路径和空字符串两种状态。空字符串的案例中，人类之后单独提供了手册目标目录，因此技能不能静默猜路径。
5. 多个案例明确要求先验收、后关闭执行终端；worktree 零残留是验收字段，不是口头承诺。
6. 历史中出现过把别的任务提交连带推送、把远端或当前 checkout 状态报告过宽、把局部测试写成整体完成等错误。技能因此要求按提交归属、证据覆盖和发布授权分别报告。
7. 阶段二不总是完整成功：有的仓库没有自有可写远端，有的长期效果、Windows 实机、独立审查或模型行为仍未验证。技能不得把“文件已修改”写成整体能力已经证明。

## 设计结论

- 两段式停点属于人类协作协议，应写入 Skill，而不是依赖每次复制长提示词。
- 真实任务和手册建设属于业务执行；阶段一提出的每条 Agent 侧建议不自动成为全局规则。
- 目标路径、Git 归属、外部发布、临时资源和人工批准是状态边界，必须在阶段二重新核验。
- 这份证据支持的是流程设计和案例模式，不支持“该技能已减少返工”或“模型一定遵循”这样的长期效果结论。
